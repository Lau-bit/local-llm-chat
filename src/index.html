Experimental. Feeds the model a map of your own concepts — distilled by Data Analysis from your past chats — as long-term conceptual memory, so it can calibrate what you already know instead of guessing. The human-browsable version lives in local-llm-vector-map.

Measured on gemma-4-26b-a4b (fully GPU-offloaded) with the 1795-concept map: Prime once costs ~22k tokens and ~3 s on the first message, then ~0.2 s per turn afterwards because the prompt prefix stays cached — an 8-turn chat held 0.5–2.3 s per turn throughout. Relevant only sends ~800–1,700 tokens per message with no upfront cost, but because that slice sits right next to your question it is the more likely of the two to pull your personal vocabulary into unrelated answers — asked how to structure error handling in Tauri, it framed the answer around personal frameworks, where priming gave a straight technical answer. Prefer priming unless you want the map kept deliberately weak.
On demand puts none of the map in the prompt and gives the model a concept_search function instead, so it pulls a handful of entries only when it judges the question needs them — the strongest available check on your vocabulary bleeding into unrelated answers, since nothing is in front of the model unless it asked. The trade: an extra round trip whenever it does search, a question it misjudges gets no map at all, and reasoning is forced off — with thinking on the model spends its whole token budget reasoning and never issues the search. Needs a model that supports tool calling; verified on gemma-4-26b-a4b. When the map holds nothing on what you asked, the search returns nothing and says so rather than offering your other topics instead — so the model answers from its own knowledge instead of bending the subject towards your usual ones. Each search appears in the transcript with what it looked for and what came back.

A local text-context layer. Point it at folders or files — e.g. your notes app's vault, exported texts — and the model reads them directly as source material. Toggle it on with the library button by the composer.

Keyword ranking misses short terms and inflections. If a vault-search service answers, it reorders the same files instead — nothing else changes, and if it does not answer this falls back silently for the rest of the session.

A browsing-history context layer. It reads your local Vivaldi (Chromium) history — the same way the Chromium History Timeline app does — and feeds the model what you've recently been looking at. Toggle it on with the history button by the composer. History is read fresh, read-only, each message; nothing is stored.

A read-only window onto the Hermes agent's warm-memory workspace — its cross-project topic notes, assessments and decision records. Toggle it on with the tiers button by the composer; it is off until you turn it on, and only the topics that match your message are retrieved. Each one is injected with its freshness stamp and where its claims came from. This app never writes to the workspace.

active/ is always searched — it is the only tier holding current topics. The rest are off by design: their material is never current evidence, so it is only ever included when it actually matches what you asked, and it is labelled as historical or untriaged when it is.
